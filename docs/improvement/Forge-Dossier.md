## 1. Overview

Workshop Forge is a voice-controlled AI assistant that runs as a dedicated appliance on a
Raspberry Pi 5 ("Lab Pi", hostname `labpi.local`, user `tyler`) in a home workshop. It
listens for a wake word ("Hey Forge"), transcribes speech, routes the request through a
layered intent system (local skills, a second-brain vault agent, or the Claude API), and
speaks the answer back through Piper TTS. A FastAPI HTTP server runs concurrently in the
same process, serving a kiosk touchscreen UI and accepting remote queries (audio or text)
from companion clients.

The Python entry point is `src/main.py`, launched by the `workshop-forge` systemd service.
A second service, `forge-ui`, launches Chromium in kiosk mode pointed at the local FastAPI
server to display the touchscreen UI.

Runtime observed on this device: **Python 3.13.5** (venv at `venv/`). Note this differs
from the README's stated "Python 3.11+" prerequisite — the live venv is 3.13.

## 2. Architecture & Data Flow

There are two top-level coroutines started by `main()` in `src/main.py` and run together
via `asyncio.gather()` (lines 146-170): the **voice pipeline** and the **API server**. The
API server is conditional on the `API_ENABLED` flag (`src/main.py:155`).

### 2.1 Voice pipeline (mic-driven)

```
Mic (Scarlett 2i4 @ 48kHz)
  → Wake Word (Porcupine, "Hey Forge")          wake_word.listen_for_wake_word()
  → STT (faster-whisper, tiny/int8)             speech_to_text.transcribe_speech_dynamic()
  → Intent classification (2-stage):
       (a) second_brain.classify_intent()  -> CAPTURE | QUERY | PROCESS | ANSWER
       (b) if vault intent  -> second_brain_agent.run()  (tool-use loop on vault)
           else (ANSWER)    -> intent_recognition.classify_intent()
                                  -> local skills first, Claude API fallback
  → TTS (Piper, voice configurable)             text_to_speech.speak()
  → Speaker (aplay -> plughw output device)
```

Detailed flow in `_voice_pipeline_inner()` (`src/main.py:52-143`):

1. `forge_state.state["status"] = "idle"`, then block in a thread on the wake-word listener
   (`src/main.py:57`).
2. On detection: status → `wake` → `listening`; record + transcribe via the configured
   dynamic-recording function (`src/main.py:66`). Empty transcripts are dropped.
3. Status → `thinking`. A short `asyncio.sleep(0.2)` is inserted before the blocking Claude
   call so `/status` (and the SSE stream) can serve the transition first
   (`src/main.py:79`, also 130).
4. **Two-stage intent**: `second_brain.classify_intent(text)` is awaited first
   (`src/main.py:81`). If it returns `CAPTURE`, `QUERY`, or `PROCESS`, the second-brain
   agent handles it in a thread (`src/main.py:85`). Otherwise `intent_recognition.classify_intent()`
   runs (`src/main.py:87`).
5. Status → `responding`. TTS playback (`text_to_speech.speak`) and a *stoppable* wake-word
   listener run concurrently (`src/main.py:96-104`) so the user can say "Hey Forge" to barge
   in mid-response.
6. **Barge-in handling** (`src/main.py:106-136`): if the wake word fires during playback,
   TTS is killed (`text_to_speech.interrupt()`), a short snippet is transcribed
   (`speech_to_text.transcribe_short`), and if it matches a stop command
   (`STOP_COMMANDS`, `src/main.py:24`) the pipeline returns to idle; otherwise the snippet
   is treated as a new query routed through `intent_recognition.classify_intent()`.
7. The outer `voice_pipeline()` wraps `_voice_pipeline_inner()` in a try/except that logs
   and restarts after a 2s sleep on any crash (`src/main.py:41-49`).

### 2.2 API request flow

```
HTTP client (Pocket Forge / HA / browser)
  POST /query  (multipart WAV)  or  POST /text  (JSON {text})
     → audio_utils.wav_bytes_to_numpy()           (only for /query)
     → speech_to_text._transcribe_with_whisper()  (only for /query)
     → second_brain.classify_intent()
          CAPTURE|QUERY|PROCESS -> second_brain_agent.run()
          ANSWER                -> intent_recognition.classify_intent(source="api")
     → audio_utils.text_to_audio_base64()  (Piper -> WAV -> base64)
  ← JSON { transcript, response, audio(base64 WAV) }
```

Defined in `src/api_server.py`: `/query` at lines 572-642, `/text` at 647-697. Both route
through the same two-stage intent classifier as the voice pipeline, with `source="api"` so
Claude conversation history is tracked separately from voice (see
[§3 claude_integration](#claude_integrationpy)).

### 2.3 Shared model instances

Whisper, Piper, and Porcupine are each loaded exactly once at module import time and shared
between the voice pipeline and the API:

- Whisper / Vosk: loaded at import of `src/speech_to_text.py` (lines 28-45).
- Piper: loaded at import of `src/text_to_speech.py` (line 18, `_voice`).
- Porcupine: created at import of `src/wake_word.py` (line 33).

## 3. Module Reference (file by file)

### `src/main.py`
Entry point and orchestrator. Sets `ORT_LOGGING_LEVEL=3`, configures logging, imports the
pipeline modules, and runs `main()` under `asyncio.run` (line 172).
Key functions:
- `is_stop_command(text)` (line 26) — substring match against `STOP_COMMANDS` (line 24).
- `voice_pipeline()` (line 30) — crash-restart wrapper; selects dynamic vs fixed recording
  via `USE_DYNAMIC_RECORDING` (line 32).
- `_voice_pipeline_inner(transcribe)` (line 52) — the main loop (described in §2.1).
- `main()` (line 146) — gathers the voice pipeline task and, if `API_ENABLED`, the API
  server task (`from api_server import start_api_server`).

### `src/wake_word.py`
Porcupine wake-word detection. On import it auto-detects a Scarlett input device by name
(lines 18-27), overriding `AUDIO_INPUT_DEVICE` if found; falls back to the settings value on
error. Creates the Porcupine instance from `PORCUPINE_ACCESS_KEY` and the `.ppn` model path
(lines 33-38). Because the Scarlett runs at 48 kHz but Porcupine expects 16 kHz, audio is
captured at `SCARLETT_SAMPLE_RATE` and resampled per frame with `scipy.signal.resample`
(lines 45, 66, 90).
Functions:
- `listen_for_wake_word()` (line 53) — blocks until the keyword is detected; auto-retries on
  audio errors with a 1s backoff.
- `listen_for_wake_word_stoppable(stop_event)` (line 75) — same loop but returns `True` on
  detection or `False` when the `threading.Event` is set; used for barge-in.

### `src/speech_to_text.py`
STT abstraction over two engines selected by `STT_ENGINE` ("vosk" or "whisper", default
"whisper"). Loads the chosen model at import (lines 28-45). Functions:
- `transcribe_speech()` (line 48) — fixed-duration record (`RECORDING_DURATION`) then
  transcribe.
- `_transcribe_with_vosk(audio)` (line 74), `_transcribe_with_whisper(audio)` (line 83) —
  engine-specific. Whisper writes a temp WAV, runs `beam_size=5, language="en"`, joins
  segments, and strips trailing punctuation.
- `transcribe_short(duration=1.5)` (line 115) — short fixed snippet, used for post-interrupt
  commands.
- `transcribe_speech_dynamic()` (line 133) — streams chunks, computes per-chunk energy
  (`np.abs(chunk).mean()`), and stops on `DYNAMIC_SILENCE_THRESHOLD` of silence or
  `DYNAMIC_MAX_DURATION`. This is the default recorder used by the voice pipeline.
The API server calls `_transcribe_with_whisper` directly on a numpy array (`api_server.py:605`).

### `src/text_to_speech.py`
Piper TTS wrapper. Loads `PiperVoice` once (line 18). Module globals `_interrupt_flag` and
`_audio_process` track an in-flight `aplay` subprocess. Functions:
- `interrupt()` (line 25) — sets the flag and kills the `aplay` process.
- `synthesize_to_wav(text)` (line 34) — synthesize to in-memory WAV bytes (used by the API
  for base64 audio).
- `speak(text, check_interrupt_callback=None)` (line 56) — runs text through
  `tts_formatter.format_for_speech`, then streams Piper chunks into `aplay` via
  `plughw:{AUDIO_OUTPUT_DEVICE},0`. Piper yields one chunk per sentence so playback begins
  before full synthesis completes. Handles `BrokenPipeError`/timeout on interrupt.
  Note: the `check_interrupt_callback` parameter is accepted but unused inside the function.

### `src/tts_formatter.py`
`format_for_speech(text)` (line 3) — regex substitutions to make text sound natural:
temperature ranges (`190-220°C` → "190 to 220 degrees Celsius"), dimensions
(`220x220x250mm` → "...by..."), and abbreviation expansions (e.g./i.e./etc.).

### `src/intent_recognition.py`
The "ANSWER"-path router: local skills first, Claude fallback. Trigger phrase lists at module
top (lines 13-18). `strip_trigger()` (line 20) removes a matched trigger phrase.
`classify_intent(text, source="voice")` (line 29) checks, in order:
1. `STOP_TRIGGERS` → "Got it." and clears Claude history.
2. `CALENDAR_TRIGGERS` → `skills.calendar.calendar_query`.
3. `CALCULATOR_TRIGGERS` → `skills.calculator.calculate` (on `ValueError`, falls back to
   Claude).
4. `TIMER_TRIGGERS` → `skills.timer.set_timer`.
5. `HOME_ASSISTANT_TRIGGERS` → `skills.home_assistant.control_device`.
6. `ALARM_TRIGGERS` → `skills.timer.stop_alarm`.
7. else → `claude_integration.ask_claude`.
Every branch logs via `query_logger.log_query` with a handler tag.

### `src/claude_integration.py`
Direct Claude API client for the ANSWER path. Creates `anthropic.Anthropic(api_key=CLAUDE_API_KEY)`
(line 22). Maintains per-source conversation history in `_history = {"voice": [], "api": []}`
and per-source last-exchange timestamps (lines 24-25).
- `clear_history(source)` (line 27).
- `log_query(question)` (line 33) — appends a timestamped line to `CLAUDE_QUERY_LOG`.
- `ask_claude(question, source="voice")` (line 40) — checks
  `budget_tracker.is_limit_reached()` first (blocks with a spoken message if so), resets
  history after `CONVERSATION_TIMEOUT`, sends `_history[source] + [user msg]`, uses model
  `CLAUDE_MODEL`, `max_tokens=CLAUDE_MAX_TOKENS`, `temperature=CLAUDE_TEMPERATURE`, with a
  hardcoded "You are Forge, a helpful workshop assistant…" system prompt (lines 67-75).
  Trims history to `CONVERSATION_MAX_TURNS*2`, records token usage via
  `budget_tracker.record_usage`, and appends a low-budget warning to the response when the
  warning threshold is crossed. Catches `anthropic.APIError` and generic exceptions with
  spoken fallback strings.
  Contains `[DEBUG]`-prefixed log lines that echo conversation history (lines 28, 31, 60).

### `src/budget_tracker.py`
Tracks cumulative Claude spend in `BUDGET_FILE` (`logs/budget.json`). Session-level
`_warning_spoken` flag resets on restart. `_EMPTY_BUDGET` schema is
`{total_cost, total_input_tokens, total_output_tokens}` (lines 21-25).
- `_load()` / `_save()` (lines 28-45).
- `is_limit_reached()` (line 48) — `total_cost >= BUDGET_HARD_LIMIT`.
- `record_usage(input_tokens, output_tokens)` (line 52) — computes cost from
  `CLAUDE_INPUT_PRICE_PER_MTOK` / `CLAUDE_OUTPUT_PRICE_PER_MTOK`, persists, and returns
  `{total_cost, warning, limit_reached}`. `warning` fires once per process when crossing
  `BUDGET_WARNING_THRESHOLD`.

### `src/query_logger.py`
`log_query(query, handler, response, error=None, source="voice")` (line 7) — appends a JSON
object per line to `logs/all_queries.jsonl` with timestamp, query, handler, response, error,
and source. `QUERY_LOG_FILE` is hardcoded to the relative path `logs/all_queries.jsonl`
(line 5), so behavior depends on the process CWD being the repo root.

### `src/forge_state.py`
A single module-level `state` dict (lines 2-7) shared in-process between the voice pipeline
(writer) and the API `/status` and `/status/stream` endpoints (readers). Keys: `status`
(`idle|wake|listening|thinking|responding`), `transcript`, `response`, `second_brain_status`
(`ready|working|error`).

### `src/audio_utils.py`
API-side audio helpers.
- `wav_bytes_to_numpy(wav_bytes, target_sample_rate=48000)` (line 15) — decodes a WAV
  (handling 8/16/32-bit, stereo→mono averaging, multi-channel decimation) and does simple
  linear resampling to 48 kHz with `np.interp`.
- `text_to_audio_base64(text)` (line 78) — calls `text_to_speech.synthesize_to_wav` and
  base64-encodes the result.

### `src/api_server.py`
FastAPI application and server bootstrap. CORS is wide open (`allow_origins=["*"]`,
lines 43-49). Static files mounted at `/static` (line 40). Bearer-token auth via
`verify_api_key` (line 54) comparing against `API_KEY` from settings (logs the invalid key
on failure, line 57). Endpoints catalogued in [§8](#8-http-api-surface). Also contains:
- Home Assistant sensor aggregation: `_ha_request` (line 64), `_fetch_sensors_data` (line 80)
  — a single bulk `/api/states` call plus a 12-hour `/api/history` query, downsampled by
  `sample_history` (line 129); shaped into a UI-friendly dict covering UniFi, temp/humidity,
  power, OctoPrint, and outlets.
- Settings read/write: `_parse_settings` / `_replace_setting_in_text` perform regex edits on
  `config/settings.py` for the allowlisted `_SETTINGS_KEYS` (lines 341-354). Changing any
  key in `_RESTART_KEYS` (lines 356-363) triggers `_restart_self_after_delay`, which calls
  `os.execv` to re-exec the process (line 441).
- GitHub webhook (`/webhook/ingress`) with optional HMAC-SHA256 verification against
  `GITHUB_WEBHOOK_SECRET` (lines 699-724), firing `ingress_processor.process_ingress` in a
  thread.
- `start_api_server()` (line 727) — runs uvicorn on `0.0.0.0:API_PORT`.

### `src/second_brain.py`
Bridge between the voice/API pipelines and the vault. On import it injects
`CLAUDE_API_KEY` into the environment, prepends `/home/tyler/second-brain` to `sys.path`,
imports `forge_capture`, and overrides all of `forge_capture`'s Windows vault paths with Pi
paths (lines 11-23). Provides:
- `classify_intent(transcript)` (line 36) — a 4-way classifier using
  `claude-sonnet-4-6` with a 10-token cap; returns one of `CAPTURE | QUERY | ANSWER | PROCESS`
  (defaults to `ANSWER` on any failure or unexpected output).
- `handle(transcript, intent=None)` (line 60) — thin wrapper delegating to
  `second_brain_agent.run`.

### `src/second_brain_agent.py`
The vault agent: an Anthropic tool-use loop with read/write access to the vault. Constants:
`VAULT = /home/tyler/second-brain`, `FORGE_LOG = Forge Log.md`, `AGENT_MD = AGENT.md`,
`MODEL = claude-sonnet-4-6`, `MAX_TOKENS = 2048`, `MAX_TOOL_ROUNDS = 15` (lines 24-29).
- `_load_system_prompt()` (line 51) — concatenates a `_BASE_SYSTEM` prompt (lines 33-48)
  with the vault's `CLAUDE.md` and `AGENT.md` if present, plus a path-override note.
- `TOOLS` (lines 79-153) — `read_file`, `write_file`, `append_file`, `list_directory`,
  `run_command` (the last constrained to a git enum: `git_pull`, `git_add_all`,
  `git_commit`, `git_push`).
- `_safe_path(rel_path)` (line 160) — resolves paths and rejects traversal outside the vault
  root.
- `_execute_tool(name, inputs)` (line 172) — dispatches the tools; `run_command` maps the
  enum to concrete git argv and runs them in the vault dir with `subprocess.run`.
- `_git_pull()` / `_git_push()` (lines 235-262) — framework-enforced git pull before and
  add/commit/push after the agent loop (independent of whatever git tools the model chose).
- `_run_agent_loop(transcript, intent)` (line 269) — sets `second_brain_status='working'`,
  pulls, seeds the conversation with today's date, then loops up to `MAX_TOOL_ROUNDS`
  executing tool calls; returns the final text block or a "ran out of steps" message.
- `_run_agent_loop_with_push` (line 319), `_run_background` (line 345),
  `_append_forge_log` (line 331).
- `run(transcript, intent=None)` (line 360) — `PROCESS` spawns a daemon background thread
  and returns "On it…" immediately; `CAPTURE`/`QUERY` run synchronously inline.
This module is the live implementation of the spec at
`docs/superpowers/specs/second-brain-agent.md`.

### `src/forge_capture.py`
A standalone interactive CLI capture/query tool for the Obsidian vault (originally authored
for a Windows machine — `VAULT = Path("C:/second-brain")` at line 27, overridden at runtime
by `second_brain.py` and `ingress_processor.py`). It loads `.env` from the vault and creates

imports it as a **library** for its helper functions and module-level path globals. Key
reusable pieces:
- Mode detection / vault scanning: `detect_mode` (65), `scan_vault_for_query` (80).
- System prompts for capture/query/project/budget/research/process (lines 157-293).
- Claude call helpers: `call_claude` (300), `call_claude_json` (311),
  `call_claude_with_web_search` (316, uses the `web_search_20250305` tool).
- Vault helpers: `find_project_file` (402), `get_vault_context` (411), `build_task_line`
  (417), `build_project_note` (428), `upsert_section` (435).
- Write helpers: `write_new_project` (466), `write_project_task` (480), `write_area_note`
  (528), `write_inbox` (538), `write_unassigned_task` (553), `execute_write` (566).
- Ingress/web helpers: `extract_url_from_text` (666), `fetch_page_content` (672, requires
  `beautifulsoup4`), `scan_ingress_files` (726).
- Git: `git_commit` (631).
Model used throughout: `claude-sonnet-4-6`. PARA-style vault folders are hardcoded
(`Projects/Active`, `Projects/Someday`, `Areas`, `Inbox`, `Resources`, `Ingress`).

### `src/ingress_processor.py`
Batch processor for files dropped into the vault's `Ingress/` folder, intended to run via
the `/webhook/ingress` endpoint or cron (commented crontab line at the top of the file,
lines 1-2). Like `second_brain.py`, it injects the API key and re-points `forge_capture`'s
vault paths to the Pi (lines 13-29). `NEEDS_REVIEW_DIR = Ingress/Needs Review`.
- `detect_target(filepath, projects, areas)` (line 38) — finds the destination project/area
  by: (1) frontmatter `forge-target:`, (2) a body `Target:` line, (3) a `[ProjectName]`
  filename prefix, (4) Claude inference (medium/high confidence only).
- `route_content(...)` (line 97) — asks Claude to choose an action
  (`append_research | create_subproject | add_tasks | append_note`) and executes it via
  `forge_capture` helpers.
- `process_ingress()` (line 154) — git-pulls, scans immediate `*.md` children of `Ingress/`,
  routes each, moves processed files to `Processed/` (or `Needs Review/` with a generated
  review file), appends to `Forge Log.md`, and commits/pushes.

### `src/skills/timer.py`
Async timer skill. `set_timer(text)` (line 115) parses a natural-language duration via
`parse_time_expression` (line 43, uses `word2number`) and schedules `start_timer`
(line 17) as a task that sleeps then plays `TIMER_ALARM_SOUND` `TIMER_ALARM_REPEATS` times
through `aplay`. `stop_alarm()` (line 31) terminates a tracked `alarm_process`. Note:
`start_timer` plays the alarm with a blocking `subprocess.run` loop and does not assign to
the module-level `alarm_process`, so `stop_alarm` cannot interrupt an already-sounding alarm.
This module calls `setup_logging()` again on import (line 10).

### `src/skills/calculator.py`
`calculate(expression)` (line 75) parses spoken math: strips commas, fixes math homophones
(`for`→`four`, `to`→`two`, etc.), maps operator words to symbols, converts number words via
`word2number`, then evaluates with `eval(parsed, {"__builtins__": {}}, {})`. Raises
`ValueError` when no operator is present or evaluation fails (which the caller treats as a
Claude-fallback trigger).

### `src/skills/calendar.py`
`calendar_query(text)` (line 3) returns the current time / date / day based on keywords.
Raises `ValueError` for unsupported queries.

### `src/skills/home_assistant.py`
Voice device control over the Home Assistant REST API. `DEVICE_ALIASES` (line 10) maps spoken
names to HA entity IDs; `DEVICE_NAMES` (line 23) maps back to friendly names.
`control_device(text)` (line 74) detects turn-on/off, resolves the device (longest alias
match first, line 67), reads `HA_TOKEN` from secrets, and POSTs to
`/api/services/{domain}/{turn_on|turn_off}` via `_ha_post` (line 39). Returns spoken
confirmations.

## 7. The Vault & Second-Brain Subsystem

The "second brain" is a separate Obsidian/Markdown vault git repository at
`/home/tyler/second-brain/` (NOT inside this repo). The Forge app interacts with it through
three code paths:

1. **Voice/API vault agent** (`second_brain.classify_intent` → `second_brain_agent.run`):
   the live, general-purpose tool-use loop. Used for spoken/typed CAPTURE/QUERY/PROCESS.
2. **Ingress batch processor** (`ingress_processor.process_ingress`): webhook/cron-driven
   routing of files dropped into `Ingress/`.
3. **forge_capture CLI** (`forge_capture.main`): an interactive REPL, used as a function
   library by (1)-via-imports historically and by (2) for its helpers. (The agent in (1)
   no longer dispatches to forge_capture write functions — it uses its own tools.)

Vault layout referenced by the code (PARA-style):
`Projects/Active/`, `Projects/Someday/`, `Projects/Archive/`, `Areas/`, `Inbox/`,
`Resources/`, `Ingress/` (with `Processed/` and `Needs Review/`), plus top-level
`Forge Log.md`, `CLAUDE.md`, and `AGENT.md`. Project notes are Markdown with frontmatter;
routing can be hinted via a `forge-target:` frontmatter field, a `Target:` body line, or a
`[ProjectName]` filename prefix.

All vault writes are followed by git pull/add/commit/push, enforced both by the agent's
allowlisted git tool and by framework-level `_git_pull`/`_git_push` calls.

The design spec for the agent is at `docs/superpowers/specs/second-brain-agent.md`; the
implementation matches it (handle() is a thin wrapper; classify_intent unchanged; PROCESS

## 8. HTTP API Surface

Base: `http://0.0.0.0:8080` (`API_PORT`). Auth: `Authorization: Bearer <API_KEY>` where
required. Defined in `src/api_server.py`.

| Method & path | Auth | Purpose |
|---|---|---|
| `GET /` | none | Serves `static/index.html` (kiosk UI), no-store. |
| `GET /health` | none | `{status, service, version}`. |
| `GET /status` | none | Current `forge_state` dict + hostname + IP. |
| `GET /status/stream` | none | SSE stream of `forge_state`; emits on change, 15s keepalive, 50ms poll. |
| `GET /sensors` | none | Aggregated Home Assistant sensor snapshot + 12h history. |
| `POST /query` | Bearer | Multipart WAV → transcript + response + base64 WAV. |
| `POST /text` | Bearer | JSON `{text}` → transcript + response + base64 WAV (no STT). |
| `GET /settings` | Bearer | Parsed allowlisted values from `config/settings.py`. |
| `POST /settings` | Bearer | Rewrites allowlisted settings; re-execs process if a restart key changed. |
| `GET /budget` | Bearer | Contents of `logs/budget.json`. |
| `DELETE /budget` | Bearer | Resets budget file to `{total_cost:0, sessions:[]}`. |
| `GET /devices` | Bearer | Audio device list from `sounddevice`. |
| `POST /test-audio` | Bearer | Speaks a test phrase in a background thread. |
| `POST /webhook/ingress` | HMAC (optional) | Fires `ingress_processor.process_ingress` in background. |

The CLAUDE.md docs describe only the `POST /query` endpoint; the live server exposes the
larger surface above.

## 11. Known Gaps, Drift & Rough Edges

Pure observations — no remediation implied.

1. **Secrets present in working tree.** `config/secrets.py` is git-ignored but exists on disk
   with live, valid-looking secrets (Anthropic key, Porcupine key, Forge `API_KEY`, HA JWT,
   GitHub webhook secret). The Forge `API_KEY` is a human-readable descriptive string.
2. **Claude model inconsistency.** The ANSWER path uses `claude-sonnet-4-20250514`
   (`settings.py`), while every vault/second-brain module hardcodes `claude-sonnet-4-6`.
   These two model identifiers coexist across the codebase.
3. **Budget schema mismatch.** `budget_tracker` reads/writes
   `{total_cost, total_input_tokens, total_output_tokens}`, but the API `GET /budget`
   FileNotFound fallback and `DELETE /budget` write `{total_cost: 0, sessions: []}` — a
   different shape than the tracker produces. The UI consumes `/budget`.
4. **`sessions` never populated.** Nothing writes a `sessions` array; the field appears only
   in the API's empty/reset payloads.
5. **CORS fully open.** `allow_origins=["*"]` with `allow_credentials=True` on the API.
6. **Invalid API keys are logged.** `verify_api_key` logs the rejected token value
   (`api_server.py:57`).
7. **Settings written by regex.** `/settings` edits `config/settings.py` via regex
   substitution and re-execs the process with `os.execv`; only allowlisted keys are handled,
   and value coercion is naive (string/bool/int/float heuristics).
8. **`calculator.eval`.** Spoken math is evaluated with `eval` (builtins disabled). Inputs are
   first transformed (homophone fixes, operator words) but the final step is still `eval`.
9. **Timer alarm cannot be stopped mid-sound.** `skills/timer.start_timer` plays the alarm via
   blocking `subprocess.run` in a loop and never sets the module-level `alarm_process`, so
   `stop_alarm()` (which terminates `alarm_process`) always reports "No alarm is playing"
   during an active alarm.
10. **No log rotation.** `logs/workshop_assistant.log` grows unbounded (already very large).
11. **Hardcoded absolute paths.** `/home/tyler/second-brain` and `/home/tyler/projects/...`
    are hardcoded in `second_brain.py`, `second_brain_agent.py`, `ingress_processor.py`, and
    the systemd units — tightly coupled to this specific machine/user.
12. **`forge_capture` Windows origin.** Default `VAULT = C:/second-brain`; relies on every
    importer to override the path globals before use. Run directly without overrides it would
    target a Windows path.
13. **Undeclared dependencies.** `beautifulsoup4`, `requests`, and `python-dotenv` are used by
    `forge_capture` but are not in `requirements.txt`.
14. **`query_logger` relative path.** Logs to the relative `logs/all_queries.jsonl`, depending
    on the process CWD (the systemd `WorkingDirectory` provides it for the service).
15. **`tts_formatter` not applied on STT side.** Only TTS output is formatted; fine, but TTS
    tuning settings (`TTS_SPEED`, `TTS_NOISE_SCALE`, `TTS_NOISE_W`) in settings.py are not
    consumed by `text_to_speech.py`.
16. **README drift.** README still says "Phase 1 - Voice Pipeline", lists only the Porcupine
    secret, points to a blog for the full plan, and states Python 3.11+ while the venv is 3.13.
17. **Docs vs. code voice.** CLAUDE.md says the TTS voice is "amy"; `settings.py` sets "alba".
18. **`check_interrupt_callback` unused** in `text_to_speech.speak`.
19. **No automated tests** are present in the repo (only a `test_query.wav` fixture).
20. **`forge-ui.service` is installed but not version-controlled** in this repo (only
    `workshop-forge.service` is committed).
